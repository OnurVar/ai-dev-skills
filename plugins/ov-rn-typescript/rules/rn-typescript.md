# React Native (TypeScript) rules

Opinionated rules for React Native 0.76+ apps written in TypeScript, New Architecture (Fabric + TurboModules) as the baseline, Hermes as the JS engine, and either bare React Native or Expo SDK 52+.

## Review behavior

Applies to any tool that reads this file via CLAUDE.md — `/pr-review-toolkit:review-pr`, `/security-review`, `/simplify`, `/code-review:code-review`, and our `/ov-rn-typescript-review-deep` orchestrator.

**Scope:** Only report findings for React Native TypeScript/JavaScript code (`.ts`, `.tsx`, `.js`, `.jsx`, Metro/Babel/Jest/ESLint config in the diff). Ignore findings about native iOS (`.swift`, `.m`, `.mm`) or native Android (`.kt`, `.java`) code — those are covered by sibling plugins.

**In-scope findings (report):**
- Correctness bugs (logic errors, race conditions, crashes, data corruption, infinite render loops, memory leaks)
- Security issues (insecure storage, TLS, secret exposure in the bundle, input-validation gaps, deep-link handling)
- React Native / TypeScript-specific concerns (hook rules, rerender hazards, FlatList perf, platform-specific code hygiene, new-architecture readiness, async lifecycle, bridge contracts from JS)
- Explicit rule violations from this file

**Out-of-scope (drop, do not report):**
- Pure style, whitespace, blank lines, import order, trailing commas
- JSDoc / TSDoc formatting
- Anything a linter/formatter/compiler catches (ESLint, Prettier, Biome, tsc, Metro bundler warnings)
- Pedantic naming, "could be shorter" suggestions
- Pre-existing issues on lines not in the diff
- Findings about native iOS/Android code not in this diff

**Confidence gate:** Report only findings you are >=80% confident are real. When in doubt, drop. Prefer false negatives over noise.

## Architecture

- **New Architecture is the baseline.** New code targets Fabric + TurboModules. Do not add new bridge (legacy) native modules; write TurboModules with codegen-backed TypeScript specs. Reanimated 4+, `react-native-screens`, and `react-native-gesture-handler` v2+ assume Fabric; if the project still runs Legacy Architecture, call that out in the PR rather than silently branching.
- **Expo-first when viable.** If the project is Expo, use config plugins (`app.json` / `app.config.ts`) for native config changes — do not edit `ios/` or `android/` directly unless you've already ejected. On bare RN, native config edits are fine but must be committed alongside the JS-side change and rebuild instructions called out.
- **Three layers — UI, domain, data.** Components (`.tsx`) talk to hooks; hooks talk to services (API clients, storage wrappers, native modules); services talk to external systems. A component must not `fetch()` or `import NativeFoo from './NativeFooModule'` directly — wrap it in a typed hook or service.
- **Server state and client state are different.** Server state (anything fetched from an API) lives in React Query / TanStack Query or SWR. Client state (UI toggles, form drafts, derived selections) lives in `useState`, `useReducer`, or an atomic store (Zustand / Jotai). Never store server data in `useState` + `useEffect(fetch)` — that's a reinvention of a query cache that gets stale, leaks, and races.
- **One screen = one file.** Do not co-locate `HomeScreen` + `ProfileScreen` in the same file. Feature folders over type folders: `features/feed/{FeedScreen.tsx, useFeed.ts, api.ts, types.ts}` beats `screens/FeedScreen.tsx + hooks/useFeed.ts + api/feed.ts + types/Feed.ts`.
- **Navigation is React Navigation v7+ with `@react-navigation/native-stack`**, or Expo Router (file-based). Never `@react-navigation/stack` (JS stack) in new code — it's slower, misses native gestures, and produces non-native large titles on iOS. For tabs, prefer `react-native-bottom-tabs` (native) or Expo Router's `NativeTabs`.
- **Monorepo rule: native deps live in the app package, not a shared library.** Autolinking only scans the app's `node_modules`. Even if `packages/ui` uses `react-native-reanimated`, `packages/app/package.json` must also list it — and both must list the exact same version (use `resolutions` / `overrides`).

## TypeScript

- **`strict: true` is non-negotiable.** Additionally enable `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, and `noImplicitOverride` in new projects. Do not add `// @ts-ignore` or `// @ts-expect-error` without a comment explaining the real reason; "tsc is wrong" is not a reason.
- **`any` and `unknown` are both banned.** Neither appears in application code. Every value has a concrete type — either hand-written or inferred from a runtime validator's output schema (Zod's `z.infer<typeof Schema>`, Valibot's `v.InferOutput<typeof Schema>`). A validator takes a raw input parameter whose type is the schema's *input* type, not `unknown`; you never need to declare `unknown` yourself. Use `never` only for exhaustiveness checks in `switch` defaults. Exception for untyped third-party imports: wrap them in a typed façade so the rest of the codebase sees concrete types, and leave a `// Third-party: no types exist for X` comment at the façade boundary — that façade still must not leak `any` or `unknown` outward.
- **Model disjoint states with discriminated unions, not flag bags.** `{ status: 'loading' } | { status: 'error', error: Error } | { status: 'success', data: T }` is correct. `{ isLoading: boolean, error: Error | null, data: T | null }` is wrong — it allows impossible states (`isLoading: true` + `data: nonNull`) and forces the reader to reconstruct the state machine mentally.
- **Exhaust `switch` on unions with `never`.** Every `switch` over a discriminated union ends with `default: const _exhaustive: never = value; throw new Error(...)`. The moment someone adds a variant, the compiler fails the build.
- **Schema validation over `as` casts and hand-written predicates.** Don't narrow with `x as User` — assertions lie silently. Don't hand-write `function isUser(x: unknown): x is User` either, since that forces `unknown` into your signature. Use a Zod / Valibot schema and `schema.parse(raw)` / `schema.safeParse(raw)`; the returned value is concretely typed via `z.infer` / `v.InferOutput`. `as unknown as T` is always wrong — if you reach for it, you need a validator.
- **Validate external data at the boundary.** Anything that crosses a wire (fetch response, deep-link params, `AsyncStorage` read, push notification payload) goes through a runtime validator (Zod / Valibot / `io-ts`) before it is used. Do not cast `response.json()` to `User` — decode it, and let `z.infer` produce the type.
- **Generics earn their keep.** Introduce a type parameter only when the relationship between inputs and outputs can't be expressed otherwise. `function identity<T>(x: T): T` is useful; `function logAndReturn<T>(x: T, label: string): T` is not (the `T` does no work here — it's just `unknown`). Over-generic signatures are harder to read and rarely catch real bugs.
- **Prefer `readonly` arrays and `as const`.** Props that a child should not mutate are `readonly T[]`. Literal arrays that drive types are `as const` (`const STATUSES = ['idle', 'pending', 'done'] as const; type Status = typeof STATUSES[number]`) — that way the type and the runtime value can't drift.
- **Component props are exported types.** `export type FooProps = { ... }; export function Foo(props: FooProps) { ... }`. Never inline `props: { a: string; b: number }` when a parent would want to reuse the shape.
- **`import type` for type-only imports.** Keeps Metro's module graph clean and lets Babel elide them; `verbatimModuleSyntax: true` enforces it.

## React & hooks

- **Rules of Hooks are non-negotiable.** Hooks run unconditionally, at the top level, in the same order every render. Any hook inside an `if`, `for`, `try/catch`, or early-return branch is a bug the compiler won't catch. If you need conditional behavior, move the conditional *inside* the hook.
- **Never set state during render.** `setState(x)` outside a `useEffect`, event handler, or derived-state pattern (computing state from props during render with an `if (prevProp !== prop) setState(...)` guard) causes infinite render loops. The common version of this bug: calling a parent callback inside the child's render to sync derived state upward.
- **Derive, don't sync.** If a value is computable from existing state/props, compute it in render — do not mirror it into state with `useEffect(() => setX(compute(a, b)), [a, b])`. That pattern adds an extra render, creates drift when the effect is skipped, and is almost always wrong. Exceptions are narrow (debounced values, cross-component event sinks).
- **`useCallback` / `useMemo` only when identity matters.** Wrap a callback or value in a memo hook only when (a) it's a dependency of a downstream `useEffect` / `useMemo`, (b) it's passed to a `memo()`-wrapped child where identity-break re-renders are measurable, or (c) the computation itself is expensive. Wrapping every handler "just in case" adds overhead without benefit and bloats dep arrays.
- **Functional `setState` when the next state depends on the previous one.** `setCount(c => c + 1)` — never `setCount(count + 1)`. The latter captures `count` via closure; multiple queued updates in the same tick will silently clobber each other, and stale closures inside async callbacks read a dead value.
- **Lazy `useState` initializers for expensive defaults.** `useState(() => buildSearchIndex(items))` runs once; `useState(buildSearchIndex(items))` runs on *every* render and throws the result away. Same for `useState(() => JSON.parse(stored))`.
- **Use `useRef` for values that must survive across renders but must not trigger a render.** Subscription handles, scroll-offset mirrors, "is this the first render" flags, timer IDs. Updating `ref.current` never re-renders — by design. Conversely, do not use `useRef` for values the UI reads; the UI won't update.
- **`useLayoutEffect` for measurements that must complete before paint.** Reading `onLayout` / `getBoundingClientRect` and feeding it back to style in a `useEffect` causes a visible one-frame flash. `useLayoutEffect` is synchronous; use it.
- **Never define a component inside another component.** Every render creates a new component type, React unmounts the old subtree and remounts the new one, destroying state, refs, input focus, and animations. Lift the inner component to module scope and pass what it needs as props.
- **`useEffectEvent` (or ref-stabilized callback) when an effect must read the latest callback without re-subscribing.** Putting an `onChange` prop directly in an effect's dep array re-subscribes every render. Wrap it in `useEffectEvent` (latest React) or a ref, and keep only the genuinely reactive values in the dep array.
- **Never put the result of `useEffectEvent` in a dep array.** Its identity intentionally changes each render; including it makes the effect re-run on every render and the React Hooks lint rule fails. Depend on the reactive inputs that drive the effect.
- **Error boundaries wrap navigation stacks, not individual components.** A render-time throw inside a screen should bubble to a per-screen boundary that can offer a retry/back action, not kill the whole app. Hooks cannot catch their own render errors — you need a class component or `react-error-boundary`.

## React Native specifics

- **Platform-specific files via `.ios.tsx` / `.android.tsx` suffixes, not runtime `Platform.OS` branches.** Metro picks the right file. Use `Platform.OS` inside a single file only for small branches (a padding difference, a color token); if a screen has 30 lines of `if (Platform.OS === 'ios')` it should be two files.
- **Strings must be inside `<Text>`.** `<View>Hello, {name}</View>` crashes at runtime with "Text strings must be rendered within a `<Text>` component". This includes whitespace — a stray space between tags inside a `<View>` will crash. The risk is highest inline in conditionals.
- **`{value && <Comp />}` is a crash landmine.** If `value` is `0` or `''`, React renders the falsy primitive as a bare number/string and crashes (outside a `<Text>`). Use `{value ? <Comp /> : null}` or `{!!value && <Comp />}`. Prefer early returns when the check gates a whole subtree. Enable `react/jsx-no-leaked-render` in ESLint.
- **Hermes is the JS engine.** Before adding `@formatjs/*` or other `Intl.*` polyfills, check the installed Hermes version's current Intl coverage — most common APIs (`Collator`, `DateTimeFormat`, `getCanonicalLocales`) are native. Unused Intl polyfills add 100+ KB to the bundle.
- **Metro does not tree-shake by default.** Barrel imports (`import { Button } from './components'`) pull every sibling export into the bundle even when only `Button` is used — and evaluate every sibling module at startup, hurting TTI. Import directly: `import Button from './components/Button'`. On Expo SDK 52+ you can opt in to experimental tree-shaking; until it's shipping without an opt-in, the discipline is manual.
- **`console.log` in production ships to the device.** Remove them from production builds via a Babel plugin (`babel-plugin-transform-remove-console` or `react-native-clean-console-log`), or gate them behind `if (__DEV__)`. Verbose logs destroy TTI and leak PII to crash reporters.
- **Reanimated shared values use `.get()` / `.set()`, not `.value`.** Required for React Compiler compatibility; `.value` access defeats the compiler's tracking. This applies even if the React Compiler is not enabled today — write forward-compatible code.
- **Turbo Module async methods for anything over 16 ms.** Sync TurboModule methods run on the JS thread and block every frame they hold; anything that does disk / network / heavy compute must be async (`Promise`-returning) so it runs on the native-modules thread. Sync is for trivial getters.
- **`AppState` listeners must clean up.** `AppState.addEventListener('change', handler)` returns a subscription; store it and call `.remove()` in the effect cleanup. Unremoved listeners outlive the component and fire into stale closures.
- **`KeyboardAvoidingView` has platform-specific behavior that does not work without the `behavior` prop.** On iOS use `behavior="padding"` (or `"position"` for specific layouts); on Android it's largely a no-op because `android:windowSoftInputMode="adjustResize"` already handles it. If the screen is a `native-stack` screen, you usually don't need it at all — `react-native-screens` handles keyboard avoidance natively.
- **`InteractionManager.runAfterInteractions(fn)` defers heavy work until after gestures/transitions complete.** Use it when a screen lands and needs to prefetch data that isn't required for first paint. Do not use it to "fix" generic slowness — that's a profiling problem, not a scheduling problem.

## Performance & lists

- **Use a virtualized list for any collection that can exceed ~20 items.** `<ScrollView>{items.map(...)}</ScrollView>` mounts every item upfront; on 500+ items it freezes for multi-second stretches and triggers memory pressure. Default: `@shopify/flash-list` (FlashList) or `@legendapp/list` (LegendList). `FlatList` is acceptable for medium lists where FlashList is overkill.
- **`keyExtractor` must return a stable, unique ID from the item — never `(_, index) => String(index)` for mutable data.** Index keys cause visual state bleeding when items reorder, delete, or insert at the head: the input in row 3 keeps its text after the row is deleted. Use a domain ID (`item.id`). Fall back to index keys only for truly static, append-only lists.
- **Do not map / filter / sort data *inside* `renderItem` or in the render body before passing to the list.** Every keystroke or unrelated parent update creates a new array reference, and virtualization treats that as "everything changed" — all visible items re-render. Stabilize upstream (via a derived `useMemo`, a selector store, or by doing the transform inside the child item).
- **`renderItem`, `keyExtractor`, `getItemType` must be stable references.** Inline arrow functions on the JSX line invalidate FlashList's recycling heuristics. Use `useCallback` (or hoist to module scope when they close over nothing). React Compiler handles this automatically when enabled; without it, memoize explicitly.
- **Pass primitives to list-item components, not the whole item object.** `<Row name={item.name} price={item.price} id={item.id} />` lets `memo(Row)` skip re-renders via shallow compare. `<Row item={item} />` re-renders whenever the parent array is reconstructed, because `item` is a new reference each pass.
- **List items must be lightweight.** No queries (`useQuery`), no heavy context reads, no expensive computations inside a row. Push data fetching to the parent and pass pre-computed values down; use atomic state (Zustand selector) inside the row when a row-local value must re-subscribe independently. A row that takes 3 ms to render costs 60 ms on a 20-item scroll burst.
- **Use `getItemType` for heterogeneous lists.** Headers, message rows, image rows, ads — each gets its own recycling pool, and a header never recycles into an image slot. Without it, FlashList mis-recycles and causes layout thrashing.
- **Check the installed FlashList major version before prescribing props.** v1 requires `estimatedItemSize`; v2+ computes it automatically and ignores the prop. Grep `package.json` first.
- **Never animate layout properties (`width`, `height`, `top`, `left`, `margin`, `padding`) with Reanimated on the UI thread.** These trigger Yoga layout every frame. Animate `transform` (scale, translate, rotate) and `opacity` — those are GPU-accelerated and don't invalidate layout. For a collapsible, scale from 0 to 1 with a fixed `height`, don't animate `height` from 200 to 0.
- **Scroll position does not belong in `useState`.** A scroll event fires per frame; `setState` on each one causes hundreds of re-renders per second and drops the UI thread. Use `useAnimatedScrollHandler` (Reanimated shared value, UI thread) for animations, or a plain `useRef` if the value is read-only by event handlers.
- **Use `expo-image` instead of `react-native`'s `<Image>` for anything in a list.** `expo-image` has proper memory-backed caching, blurhash placeholders, `recyclingKey`, and `cachePolicy` props. Native `<Image>` leaks memory in long lists and has no built-in placeholder.
- **Request thumbnails sized to the display, not full-resolution originals.** Rendering a 4000×3000 photo at `{ width: 100, height: 100 }` uses ~50 MB of decoded pixel memory per item. Use your CDN's resize params (`?w=200&h=200&fit=cover`) — target 2x the display size for retina.

## State management & data

- **React Context is not a state manager.** Every consumer re-renders when any value in the context changes. Use Context for truly ambient values (theme, current user, locale). For frequently-changing global state, use Zustand or Jotai — both support selector subscriptions, so a store slice change only re-renders components that selected that slice.
- **Zustand selectors must return the minimal needed value, not the whole store.** `useStore(s => s.cart.items)` is correct; `useStore()` re-renders on every unrelated change. For object/array selects, pair with `shallow` to avoid reference-equality re-renders.
- **Server state → React Query / TanStack Query / SWR.** Never `useState + useEffect(fetch)` for anything the server owns. A query cache gives you request deduplication, retry, stale-while-revalidate, cache invalidation, and refetch-on-focus for free. The manual version is always buggy.
- **Lift state up, then push selectors down.** State belongs at the lowest common ancestor. When performance matters (a list row reading a slice of a global store), reach for a selector-based store (Zustand) so the parent doesn't re-render — the children that selected that slice do.
- **State holds user intent and server truth, nothing derived.** Store the minimum: the `selectedIds: Set<string>`, not `selectedItems: Item[]` (derive it). The `query: string`, not `filteredItems`. Two pieces of state that can disagree always will.
- **Persist client state sparingly and explicitly.** `AsyncStorage` + `redux-persist` / `zustand/persist` is fine for UX preferences (theme, last tab). It is *not* fine for secrets, tokens, or PII — see Security. And it is not fine for large arrays; reads and writes are async and serialize/deserialize the whole value every time.
- **Normalize server data only when you need to join or cross-reference.** A flat `Record<Id, Entity>` + lookups beats nested structures for editing and consistency. For purely view-model data (a single list of messages), denormalized is fine and cheaper.

## Async & effects

- **Every `useEffect` that starts async work must handle cancellation.** The component can unmount, the dep keys can change, and the promise will still resolve into a dead component — `setState` after unmount warns, but worse: the fetched data gets dropped on the floor while holding a reference to the closed-over component. Use an `AbortController` with `fetch(url, { signal })` and abort in cleanup, or a local `let cancelled = false` / `if (cancelled) return` guard.
- **Cleanup functions must reverse every setup.** `addEventListener` → `removeEventListener`. `setInterval` → `clearInterval`. `setTimeout` → `clearTimeout`. `subscribe()` → `unsubscribe()`. `addListener` → `remove()`. Skipping cleanup in dev *seems* fine because StrictMode runs effects twice and catches some cases — it does not catch cleanups for intervals/timers.
- **`Promise.all` for independent requests, `Promise.allSettled` when partial success is acceptable.** Sequential `await`s for independent work add round-trips for no reason. `Promise.all` rejects on the first failure; use `allSettled` when the UI should render what succeeded even if one failed.
- **Race conditions: the last request must be the one that wins.** Typing "react native" in a search box kicks off requests for "r", "re", "rea"... and any one of them can return last. Guard with an `AbortController` per request + abort-previous, or a "request id" check (`if (reqId !== latestReqId.current) return`), or use a library (React Query / SWR) that handles this.
- **`try/catch` around `await`, not around the whole effect.** A `try { const x = await f(); setState(x) }` that also catches the setState throws away real bugs (render errors) alongside the fetch error. Catch the fetch specifically; let render errors bubble to an error boundary.
- **Never `await` inside a render.** Rendering is synchronous. If you need async data, use Suspense + a query library, or render a loading state and kick off the fetch in an effect.
- **App-wide init runs once in `index.js` / `App.tsx` module scope, not inside a component's `useEffect([])`.** Components can remount (navigation, StrictMode); module-scope initialization runs once. If init must be inside React (because it needs a provider), use a module-level `didInit` guard.
- **`setTimeout` inside render, or with dynamic durations stored in state, is a smell.** If you need "do X after Y ms", model the time as state + an effect that clears the timer on unmount; or use a hook (`useTimeout`) that owns the lifecycle.

## Navigation

- **React Navigation v7+ with `@react-navigation/native-stack`**, or Expo Router (file-based) on Expo. Legacy `@react-navigation/stack` is banned in new code — JS transitions are visibly slower than native, and it misses iOS large titles, blur headers, and swipe-back gestures that native-stack gets for free.
- **Tabs: prefer native.** `react-native-bottom-tabs` (native iOS `UITabBar` / Android material) or Expo Router's `NativeTabs`. `@react-navigation/bottom-tabs` (JS) ships a non-native feel — tab taps don't scroll-to-top, there's no picture-in-picture inset handling, and the blur behind iOS is approximate.
- **Typed navigation. No string-keyed routes without types.** Declare `type RootStackParamList = { Home: undefined; Profile: { userId: string } }`, register it with `declare global { namespace ReactNavigation { interface RootParamList extends RootStackParamList {} } }`, and every `navigation.navigate('Profile', { userId })` is now checked. Untyped `navigate('profile', { user_id })` (note: typo) compiles and crashes at runtime.
- **Deep linking config is a security surface, not just a convenience.** A `Linking.getInitialURL()` handler that routes based on untrusted URL params is the most common React Native vulnerability in review. Validate that the URL's host matches your expected domain(s), that the path matches one of a whitelist, and that params are typed and range-checked before routing. Never pass a URL param straight into `navigation.navigate(...)` without validation.
- **Safe areas: use `react-native-safe-area-context` or native header/tab handling.** On iOS with `native-stack`, `contentInsetAdjustmentBehavior="automatic"` on the screen's `ScrollView` makes content scroll correctly behind the translucent header and tab bar — you usually do not need a wrapping `SafeAreaView`. On Android, safe area mostly means status-bar height; a top `useSafeAreaInsets().top` padding is enough. Do not hardcode `44` for the iOS header height — it's wrong on iPads and with large titles.
- **Prefer native modal presentations over JS-based bottom sheets when the content is a full sheet.** `navigation.navigate('Sheet')` with `{ presentation: 'formSheet', sheetAllowedDetents: 'fitToContents' }` gives you swipe-to-dismiss, keyboard avoidance, and accessibility for free. Reach for `@gorhom/bottom-sheet` only when you need deep gesture/animation customization; for everything else, use `react-native-true-sheet` (fully native, requires Fabric) or the built-in modal.
- **State that describes "which screen is open" belongs to the navigator, not your store.** Do not mirror `route.name` into a Zustand atom. React to navigation events via `useFocusEffect` / `useIsFocused` when you need to refresh data on focus.

## Security

- **`AsyncStorage` is plaintext.** It is not a secrets store. Tokens, refresh tokens, API keys, PII, session IDs, biometric data — none of these belong in `AsyncStorage`. On a rooted Android device or a jailbroken iOS device, the entire store is readable.
- **Use `react-native-keychain` (or Expo `SecureStore`) for secrets.** On iOS it maps to the Keychain (hardware-backed on modern devices); on Android to EncryptedSharedPreferences / KeyStore. Set `accessible: ACCESSIBLE.WHEN_UNLOCKED_THIS_DEVICE_ONLY` for tokens that shouldn't migrate to a new device via iCloud restore. Prefer biometric gating (`accessControl: BIOMETRY_CURRENT_SET`) for high-value credentials.
- **No secrets in the JS bundle, ever.** Anything imported into your TS code ends up readable in the shipped `.bundle` file. That includes API keys for "internal" services, Firebase web keys (these are public by design — fine), and signing keys (catastrophic). Use a proxy server or short-lived tokens issued from a backend. `EXPO_PUBLIC_*` env vars are exposed; non-prefixed `.env` values on Expo are not bundled but shouldn't be relied on as "secret" either.
- **Deep link params are attacker-controlled input.** `myapp://pay?amount=100&to=bob` can arrive from any app. Validate the host, validate path, validate each param's type and range. Never read a deep-link URL into a `WebView`'s `source`. Never navigate to a screen that performs a side effect (delete, pay, grant permission) based on a deep link without an explicit user confirmation step.
- **WebViews are sandboxes around untrusted code.** Set `originWhitelist` to the narrowest possible list; disable `javaScriptEnabled` unless you actually need it; disable `allowFileAccess`, `allowingReadAccessToURL`, `allowUniversalAccessFromFileURLs`; never inject user data into the HTML content with string concatenation (use `injectedJavaScript` with escaped values, or better, `postMessage` over `window.ReactNativeWebView.postMessage`). Validate every `onMessage` payload through a schema (Zod / Valibot) before use — do not trust a raw `event.nativeEvent.data`.
- **TLS is not optional, and self-signed / bypassed is not acceptable.** Do not set `NSAllowsArbitraryLoads` to `YES` in `Info.plist`. Do not monkey-patch `global.XMLHttpRequest` to skip cert checks. For defense in depth against CA compromise, implement certificate pinning for production APIs (`react-native-ssl-pinning` or via a TurboModule) — at minimum pin the intermediate CA.
- **OTA updates must be signed.** Expo Updates (EAS Update) and CodePush both support signing. Unsigned OTA is a supply-chain vulnerability: anyone who compromises your update server can ship arbitrary JS to every user. Verify `expo-updates` has `EXPO_UPDATES_CODE_SIGNING_*` configured or `CodePush.checkForUpdate` uses a signing key.
- **Validate push-notification payloads before acting on them.** An FCM / APNs payload can be triggered by anyone with your server key if it leaks. Decode the payload through a schema before use, and do not execute navigation / mutations based on a raw field without a server-side confirmation.
- **PII and logs.** Do not `console.log(user)` in production, do not log tokens, do not send raw request/response bodies to crash reporters (Sentry, Bugsnag) — strip known-sensitive fields via `beforeSend` / `onBreadcrumb`. Don't put emails, phone numbers, or IDs in breadcrumbs.
- **Clipboard and share sheets are information-exfiltration surfaces.** `Clipboard.setString(token)` to "copy my token" is a common foot-gun; the clipboard is readable by any app on iOS (including with some delay after the app backgrounds). If you must expose a token, set a short clipboard TTL on iOS 14+ (`setStringAsync(..., { expiresIn })` via Expo Clipboard).
- **Root / jailbreak detection is defense in depth, not a security boundary.** Use `jail-monkey` or similar to detect and gate high-value actions (payments) on rooted devices — do not rely on it as your only control. A determined attacker can patch around any JS-side check.

## Testing

- **React Native Testing Library (`@testing-library/react-native`) for component tests, not `react-test-renderer` directly.** RNTL gives you accessibility-first queries (`getByRole`) and cleanup semantics. Check the installed major version before assuming sync vs async signatures — newer majors are fully async and must be `await`ed.
- **Query priority: `getByRole` > `getByLabelText` > `getByPlaceholderText` > `getByText` > `getByDisplayValue` > `getByTestId`.** `testID` is a last resort — a test that passes because `testID="submit-btn"` exists tells you nothing about whether the user can actually tap it. `getByRole('button', { name: 'Submit' })` tests the accessibility tree, which is what screen readers see.
- **`getBy*` when the element must exist (throws if missing); `queryBy*` only for `.not.toBeOnTheScreen()` non-existence checks; `findBy*` for async / waitFor cases.** Do not `await waitFor(() => expect(getByText(...))...)` — use `expect(await findByText(...))...`. `waitFor` callbacks must contain one assertion and no side effects; a `fireEvent.press` inside a `waitFor` retries the press on every tick.
- **Prefer `userEvent` over `fireEvent`.** `await user.press(btn)` runs the full press lifecycle (`onPressIn`, `onPress`, `onPressOut`) and is async; `fireEvent.press` fires only `onPress` and skips focus / hover. `user.type(input, 'Hello')` types character-by-character with focus/blur events; `fireEvent.changeText` sets the text atomically, which does not match real user behavior.
- **Do not wrap `render` / `fireEvent` / `userEvent` in `act()` manually.** All three handle `act` internally. Manual `act` wrapping produces false passes and misleading error messages.
- **Don't destructure queries from `render()`.** Use the `screen` object: `render(<Comp />); screen.getByText(...)`. Destructuring makes queries local to a setup that might drift from reality after an interaction.
- **Mock the network at the fetch layer.** `msw` (Mock Service Worker) with the `msw/native` adapter runs across the whole test and catches requests you didn't mock — that catches real bugs. Mocking `axios` / `fetch` per-test is brittle.
- **Native modules get mocked, not stubbed in-place.** `jest.setup.ts` registers module mocks (`jest.mock('react-native-keychain', () => ({ setInternetCredentials: jest.fn() }))`). Do not call real native code from a Jest test — there's no native runtime, and behavior diverges.
- **Snapshot tests are a liability by default.** Large JSX snapshots turn into accepted-without-reading noise on the PR that caused them to change. Use snapshots only for small, intentional, rarely-changing surfaces (e.g., a generated theme tokens object). For UI correctness, write assertions: "has a button named Submit that is enabled".
- **Detox (or Maestro) for end-to-end UI flows on a real device/simulator.** RNTL is for component logic; it does not exercise real navigation, real native UI, or real native-backed state. E2E is where login flows, deep links, and cross-screen integration live.

## Accessibility

- **Every interactive element has a label.** A `<Pressable>` wrapping an icon with no text must have `aria-label`; otherwise screen readers announce "button, button" with no context. A `<Pressable>` wrapping text can rely on the child `<Text>` for its name.
- **`<View>` is not focusable by default.** To make a container element tappable-and-announced, use `<Pressable>` (or a `<Button>`), not `<View onTouchEnd={...}>` with manual `accessible={true}`. Platform-native traits (press feedback, focus ring) come with `Pressable`.
- **Minimum tap target is 44pt iOS / 48dp Android.** When the visible icon is smaller (say, a 20pt close X), use `hitSlop={{ top: 12, bottom: 12, left: 12, right: 12 }}` to extend the hit area. Tiny tap targets fail WCAG 2.5.5 and cause real frustration.
- **Respect Dynamic Type / font scale.** `fontSize: 14` in a `StyleSheet.create` will scale on iOS by default unless you opt out — do not set `allowFontScaling={false}` on body text; reserve it for fixed-chrome like tab labels where layout would break. Test with iOS "Larger Accessibility Sizes" turned on at least once per screen.
- **RTL: flip with `I18nManager` and logical properties.** Use `paddingStart` / `marginEnd` over `paddingLeft` / `marginRight`. Icons that imply direction (arrows, back chevrons) must flip when RTL is active — they don't flip automatically.
- **Focus management on navigation.** When a screen mounts, focus should land on a meaningful element (the title, the primary action) — not the first traversed View. Use `AccessibilityInfo.setAccessibilityFocus(reactTag)` from a `useFocusEffect` on key screens. Screen readers that land on "`<back button>`" are a regression.
- **Never rely on color alone to convey state.** A red border for an invalid field fails for color-blind users and for anyone with high-contrast mode. Pair color with an icon, text, or an `aria-invalid` / `role="alert"` element that is announced.
- **Label bottom-sheet / modal content.** When a sheet opens, it must be its own accessibility region with a name; otherwise VoiceOver continues to read the background while the user interacts with the sheet. Use `accessibilityViewIsModal` (iOS) and `importantForAccessibility="yes"` / `"no-hide-descendants"` on the background siblings (Android).
